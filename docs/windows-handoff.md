> Android Studio supplies it to the IDE but not to a terminal Gradle build. `android/local.properties`

## 5. First run

```powershell
npm install
npx expo prebuild --platform android
npx expo run:android
```

`npx expo run:android` **builds, installs, and then keeps running to serve Metro** — it is not
supposed to exit. Leave it running; press `r` to reload.

Expo Go **cannot** run this app: `expo-share-intent` (M8) and the date picker need native code, so
a custom dev client is required. That is why `prebuild` is in the loop.

`/android` and `/ios` are **not committed** — they are regenerated by prebuild.

Verify the toolchain any time with:

```powershell
npx expo-doctor      # should report all checks passing
npm test             # 249 tests
npx tsc --noEmit     # must be clean
```

## 6. A device to run on

**Emulator:** Android Studio → Device Manager → Create Device. Pick any phone, system image
**API 36**, and set **internal storage to 12GB or more**.

> Do not skip the storage setting. On the Mac the default 6G partition filled to 93% and the
> install failed with `INSTALL_FAILED_INSUFFICIENT_STORAGE` — a debug APK is ~89MB and needs
> several times that free.

**Physical Galaxy S26 Ultra:** Settings → About phone → tap *Build number* seven times, then
Developer options → **USB debugging**. Connect by USB, confirm with `adb devices`, then
`npx expo run:android --device`.

On a personal machine the Mac's data-flow restrictions (`CLAUDE.md` §9) no longer apply — those
existed because the laptop was company-managed. **One rule still does:** install a **release**
build for real travel use, never the dev build. A debuggable build lets any authorised computer
read the app's private sandbox — the database and every imported PDF — via `adb shell run-as`.

## 7. Windows-specific gotchas

**Long paths.** `node_modules` nests deeply and Windows defaults to a 260-character limit.

```powershell
git config --global core.longpaths true
# and, as Administrator:
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" `
  -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force
```

**Neither of those is enough — keep the repo at a short path, e.g. `C:\dev\travel-organizer`.**
Found on the first Windows build: from `C:\Users\<you>\Desktop\repos\travel-organizer` the build
failed in `buildCMakeDebug` with `ninja: error: Stat(...RNGestureHandlerDetectorShadowNode.cpp.o):
Filename longer than 260 characters`. CMake mirrors the **absolute** source path inside
`android/app/.cxx/...`, so the repo path is counted twice, and the NDK's ninja enforces 260
characters regardless of `LongPathsEnabled`. Moving the repo to `C:\dev` fixed it with no other
change.

**npm 11 blocks install scripts by default.** `better-sqlite3` needs its install script for the
node SQL tests; `package.json` carries an `allowScripts` entry for it, so a fresh `npm install`
just works. If it is ever bumped, re-run `npm install-scripts approve better-sqlite3`.

**Gradle memory.** If the build dies with an OOM, raise the heap in `android/gradle.properties`:

```properties
org.gradle.jvmargs=-Xmx4096m -XX:MaxMetaspaceSize=512m
```

Note that file is regenerated by prebuild, so prefer an `app.json` config or re-apply it.

**Antivirus.** Real-time scanning of `node_modules` and the Gradle cache slows builds
considerably. Excluding the project folder and `%USERPROFILE%\.gradle` is a large win.

**Line endings.** `git config --global core.autocrlf input` keeps the repo LF-only.

**Emulator acceleration.** Needs Windows Hypervisor Platform (WHPX) enabled in
*Turn Windows features on or off*.

**Running the app on this machine.** The repo lives at `C:\dev\travel-organizer` (see §7).
Run `npx expo run:android` in a terminal you can see. Once, with its output redirected to a file,
it printed nothing and never started Gradle — most likely waiting on a prompt nobody could see.
Don't use `CI=1` to get past that: in CI mode it ignored the running emulator, tried to launch one
with an empty name, and quit before building.

What worked on 2026-09-15, with Metro already running in another terminal: name the device, skip
the dependency check, and leave the bundler to that Metro.

```bash
EXPO_NO_DEPENDENCY_VALIDATION=1 npx expo run:android --device Pixel_10_Pro --no-bundler
EXPO_NO_DEPENDENCY_VALIDATION=1 npx expo start --dev-client   # the Metro, in its own terminal
```

**The core is done, so S work is wiring known-good tested functions to screens.** Read the
function's tests before designing a screen around it — they state the intended behaviour more
precisely than the docs do.

**Three findings already paid for — do not rediscover them:**

1. `getContentUriAsync` **typechecks but throws at runtime**. The modern `expo-file-system`
   exports it only as a deprecation shim. Use `new File(path).contentUri`
2. `SQLiteProvider` needs `options={{ enableChangeListener: true }}`. It defaults to `false`, and
   without it every live query silently shows stale data — no error, no warning
3. `Intl.supportedValuesOf('timeZone')` does **not exist** on Hermes, hence the curated list in
   `src/domain/timezones.ts`
4. `File.copy()` **returns a promise** in expo-file-system 57.0.6 and must be awaited, or a
   resource row can be written before its file lands
5. A form bound to a Zod schema with `.default()` must hold `z.input`, not `z.output` — see
   `ItemForm`. `tripItemInputSchema(tz)` also returns a **new object per call**, so memoize it
6. **Never write through `withExclusiveTransactionAsync`** in app code that screens read live. It
   opens a second connection, the change listener never hears its writes, and every `useLiveQuery`
   stays stale until a relaunch. Use `withTransactionAsync`. (Found in S5: Home showed *No trips yet*
   after a successful import.)

## Release build (S8)

The build to travel with. It isn't debuggable, it needs no Metro, and it's signed with a **private
key** that lives outside the repo:

- `%USERPROFILE%.travel-organizerelease.jks` — the keystore
- `%USERPROFILE%.gradlegradle.properties` — `TRAVEL_ORGANIZER_STORE_FILE`, `_STORE_PASSWORD`,
  `_KEY_ALIAS`, `_KEY_PASSWORD`, read by `plugins/withReleaseSigning.js`

> **Back both up somewhere safe, such as a password manager or an encrypted drive, never the repo.**
> Android only accepts an update signed with the same key. Lose it, and the next version can only
> be installed after uninstalling, which deletes every trip unless a backup was exported first.

```bash
npx expo prebuild --platform android      # after any app.json or native change
cd android && ./gradlew assembleRelease   # ~9 min cold, ~1 min when only JS changed
# → android/app/build/outputs/apk/release/app-release.apk (all ABIs, ~115 MB)
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

Certificate SHA-256 `63:8D:C6:86:…:52:35:E7`. Check any APK with `apksigner verify --print-certs`.
A copy of the S8 build is at `%USERPROFILE%.travel-organizer	ravel-organizer-0.1.0.apk`.

To switch the emulator between the dev build and the release, uninstall first: they are signed with
different keys. Test data for the release comes from `node scripts/sample-backup.mjs`, pushed to
Downloads and imported.

## Notes from S6 and S7

- **After a native build, if the dev client sits on a white screen**, time `curl localhost:8081/status`.
  Twice Metro was alive but taking 14s or more to answer, and it only recovered after a restart.
  Stop the Gradle daemons (`android/gradlew --stop`) and restart Metro.
- **Use `adb reverse tcp:8081 tcp:8081` and `url=http://localhost:8081`** in the dev-client link. The
  LAN IP changes between sessions (it was 192.168.0.3, then 192.168.0.6).
- **If the emulator hangs at boot** with *OpenGL Core Profile not supported*, start it with
  `emulator -avd Pixel_10_Pro -gpu swiftshader_indirect`.
- **Testing a file share from adb:** `--grant-read-uri-permission` does not cover the `STREAM` extra,
  so the app cannot read the file. Share from the Files app instead, which grants it properly.

## Note for S5 (export/import)

Built in S5 — see `docs/technical-reference.md` §12 *The archive*. The zip is `fflate` (pure JS, no
rebuild), but the share sheet is `expo-sharing`, which is native: after installing it the app needed
`npx expo prebuild --platform android` and a dev-client rebuild. With uncommitted changes, set
`EXPO_NO_GIT_STATUS=1` so prebuild does not stop at its "continue?" prompt.
